# 综合项目 P14：低功耗环境节点（Low Power Environment Node）

## 1. 项目简介

电池供电的物联网设备通常不能一直全速运行，否则会很快耗尽电量。本项目实现一个典型的**低功耗环境节点**：ESP32 每 10 分钟从 Deep Sleep（深度睡眠）中唤醒一次，读取 DHT22 温湿度数据，通过 Wi-Fi 以 HTTP GET 方式发送到服务器，然后再次进入深度睡眠。

项目同时展示了：
- **RTC 内存**：记录“本次通电以来第几次启动”，在 Deep Sleep 期间不丢失。
- **Preferences**：保存服务器地址和累计上报次数，断电后仍然保留。
- **省电循环设计**：采集 → 上报 → 睡眠，让设备可以用电池长期运行。

学完本项目，你将掌握设计低功耗物联网节点的核心思路。

## 4. 电路连接

| ESP32 引脚 | 连接器件 | 备注 |
|------------|----------|------|
| 3.3V | DHT22 VCC | DHT22 可直接用 3.3V 供电 |
| GND | DHT22 GND | 共地 |
| GPIO4 | DHT22 DATA | 读取温湿度 |

> 本项目为了低功耗，没有接 LED。如果接了 LED，Deep Sleep 期间 LED 会熄灭，但限流电阻本身不耗电。

## 5. 代码思路

整个程序的生命周期完全在 `setup()` 中完成，`loop()` 中不会执行任何代码，因为每次任务结束后 ESP32 都会进入 Deep Sleep。

1. **启动（setup）**
   - 等待串口就绪。
   - `bootCount++`：用 RTC 内存统计本次通电后的启动次数。
   - 打印唤醒原因（定时器唤醒 / 普通复位等）。
   - 初始化 DHT22。
   - 从 Preferences 加载目标服务器地址和历史累计上报次数。
   - 读取温湿度。如果失败，直接睡眠。
   - 连接 Wi-Fi，通过 HTTP GET 把数据上报到服务器。
   - 上报成功后，累计次数加 1 并保存到 Preferences。
   - 等待最多 5 秒，处理串口调试命令。
   - 配置定时器唤醒，进入 Deep Sleep。

2. **唤醒**
   - 10 分钟后，ESP32 被定时器唤醒，自动复位，重新执行 `setup()`。
   - `bootCount` 由于放在 RTC 内存中，会在上次基础上继续累加。

## 6. 关键代码解析

### 6.1 RTC 内存变量

```cpp
RTC_DATA_ATTR int bootCount = 0;
```

**为什么要用 `RTC_DATA_ATTR`？**  
普通变量在 Deep Sleep 后会丢失，因为 CPU 和 RAM 都会断电。RTC 内存由独立电源域供电，可以在睡眠期间保持数据。把 `bootCount` 放在这里，我们就能知道“这是本次通电以来的第几次启动”。

### 6.2 定时器唤醒配置

```cpp
#define SLEEP_TIME_US 600000000ULL
esp_sleep_enable_timer_wakeup(SLEEP_TIME_US);
esp_deep_sleep_start();
```

- `SLEEP_TIME_US` 是微秒，10 分钟 = 600 秒 = 600,000,000 微秒。
- `esp_sleep_enable_timer_wakeup()` 配置唤醒源。
- `esp_deep_sleep_start()` 真正进入睡眠，CPU 停止运行。

**为什么这里用 `ULL` 后缀？**  
`600000000` 这个数超出了 32 位有符号整数的范围（约 21 亿），不加 `ULL` 会被编译器当成 `int` 处理，导致数值溢出。

### 6.3 Preferences 保存配置

```cpp
Preferences prefs;
prefs.begin("envNode", false);
serverUrl = prefs.getString("serverUrl", "http://192.168.1.100:8080/upload");
prefs.end();
```

- 服务器地址会保存在 Flash 中，断电不丢失。
- 第一次运行时如果 Preferences 里没有数据，会使用代码中设置的默认值。
- 用户可以通过串口命令 `config http://...` 修改目标服务器，无需重新烧录程序。

### 6.4 HTTP GET 上报

```cpp
String url = serverUrl;
url += "?temp=" + String(temp, 2);
url += "&hum=" + String(hum, 2);
url += "&boot=" + String(boot);
http.begin(url);
int httpCode = http.GET();
```

- 使用 URL 查询参数传递数据，服务器端解析简单。
- `String(value, 2)` 把浮点数保留两位小数。
- 服务器返回 200 表示接收成功。

## 8. 常见问题

| 问题现象 | 可能原因 | 排查方法 |
|----------|----------|----------|
| 每次启动次数都显示 1 | RTC 内存被断电清除了 | 正常行为：拔掉 USB 或按下复位键都会让 RTC 内存丢失；定时器唤醒时才会继续累加 |
| 无法连接 Wi-Fi | SSID/密码错误、5GHz Wi-Fi、信号弱 | 检查代码中的 Wi-Fi 信息；ESP32 只支持 2.4GHz；靠近路由器测试 |
| HTTP 状态码 -1 或连接失败 | 服务器地址错误、ESP32 与服务器不在同一网络 | 在电脑浏览器中打开同样 URL 测试；检查 IP 和端口 |
| DHT22 读取失败 | 接线松动、缺少上拉、启动时传感器未稳定 | 检查接线；DATA 与 3.3V 之间加 4.7kΩ 上拉；Deep Sleep 唤醒后给 DHT 留足初始化时间 |
| 程序进入睡眠后串口无响应 | Deep Sleep 会关闭 CPU | 正常现象，只能等待定时器唤醒或按下复位键 |
| 实测电流下降不明显 | 开发板上的 USB 转串口芯片、电源指示灯耗电 | 要测真实低功耗时，应使用裸模块或专门低功耗板，并断开 USB |

## 9. 扩展挑战

1. **增加外部手动唤醒按钮**：在 GPIO33 接一个按键到 GND，用 `esp_sleep_enable_ext0_wakeup()` 实现按下按键立即唤醒并上报。
2. **服务器端接收程序**：用 Python Flask 写一个接口 `/upload`，把 GET 参数保存到 SQLite 数据库或 CSV 文件，实现远程数据可视化。
3. **失败重试与本地缓存**：如果某次上报失败，把数据存到 RTC 内存或 Preferences，下次唤醒时一起批量发送，避免数据丢失。
4. **优化功耗**：关闭 Wi-Fi 后再进入 Deep Sleep、降低 CPU 频率、移除开发板上的电源指示灯，实测电池续航时间。
