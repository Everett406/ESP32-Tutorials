# ESP32 教程编写风格指南

## 总体要求

1. **目标读者**：完全零基础、刚开始接触 ESP32 和 Arduino 的人。
2. **一个示例只讲一个核心知识点**，不要贪多。
3. **中文注释要详细**，但不要为了注释而注释，要解释"为什么"。
4. **遇到专业名词必须展开解释**，不能一笔带过。

## 文件结构

每个教程目录下只有一个 `.ino` 文件，文件名与目录名一致。

```
XX_Topic_Name/
└── XX_Topic_Name.ino
```

## 代码注释结构

### 1. 顶部大注释（必须）

包含：
- 教程标题和编号
- 学习目标（3-5 条）
- 前置知识（如果需要）
- 硬件连接说明
- 关键概念解释（如果本课引入了新概念）

### 2. 宏定义和变量声明

每个宏和关键变量都要解释：
- 这个值为什么是这个数字？
- 这个引脚为什么选它？
- 如果不选这个会怎样？

### 3. setup() 函数

按步骤解释：
- 为什么要初始化这个？
- 这个函数做了什么？
- 参数分别代表什么？

### 4. loop() 函数

解释主循环的逻辑流程，关键代码行必须有注释。

### 5. 自定义函数

解释函数的作用、参数、返回值。

### 6. 扩展练习

在文件末尾用注释给出 2-3 个扩展方向。

## 名词解释规则

只要教程中第一次出现以下类型的名词，必须在附近用注释或段落解释清楚：

- 协议类：UART、I2C、SPI、HTTP、TCP/IP、MQTT、BLE、SPP、OTA
- 硬件类：GPIO、ADC、PWM、DAC、RTC、NVS、Flash、上拉电阻、占空比
- 软件类：ISR、任务（Task）、堆栈、回调函数、JSON、API
- 网络类：IP、SSID、MAC、DNS、mDNS、端口、路由、AP/STA

解释方式示例：

```cpp
// PWM（Pulse Width Modulation，脉宽调制）：
// 它不是真正的"模拟输出"，而是让引脚快速地在高电平和低电平之间切换。
// 如果高电平时间占总周期的比例大，LED 看起来就更亮；比例小就更暗。
// 这个比例就叫"占空比"（Duty Cycle）。
```

## "为什么"的解释示例

不要只写：

```cpp
pinMode(LED_PIN, OUTPUT);  // 设置 LED 引脚为输出
```

要写成：

```cpp
// pinMode(pin, mode) 用来告诉 ESP32 这个引脚要做什么用。
// 这里把 LED_PIN 设为 OUTPUT（输出模式），
// 因为我们要让 ESP32 主动控制 LED 的亮灭。
// 如果设为 INPUT（输入模式），引脚只能读取外部信号，无法驱动 LED。
pinMode(LED_PIN, OUTPUT);
```

## 代码风格

- 缩进：2 个空格
- 变量名：用英文，小写加下划线
- 宏定义：全大写
- 每行不要太长，超过 80 字符考虑换行
- 中英文之间加空格

## 硬件连接说明格式

```cpp
/*
 * 硬件连接：
 * - ESP32 GPIO2  →  LED 正极（长脚）
 * - LED 负极（短脚） →  330Ω 电阻  →  GND
 *
 * 为什么要加电阻？
 * LED 导通后内阻很小，直接接 3.3V 会烧坏。
 * 330Ω 电阻限制电流，让 LED 安全工作。
 */
```

## ESP32 Arduino 3.x API 注意

- PWM 用 `ledcAttach()` 和 `ledcWrite()`
- 定时器用 `timerBegin()`、`timerAttachInterrupt()`、`timerAlarm()`
- 不要用已废弃的 `ledcSetup()` / `ledcAttachPin()` / `timerBegin(freq)` 老写法

## 扩展项目编写要求

扩展项目（extensions/）和 外设项目（peripherals/）也要遵循以上规则，但需要额外说明：
- 需要安装哪些库（库名称、版本、安装方法）
- 详细的接线图或表格
- 常见错误和排查方法
